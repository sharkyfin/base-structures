# Базовые структуры

ЛР-1, C++17. Здесь собраны все структуры данных, включая словари и отсортированную последовательность, используемые в `search-and-data`.

Общие файлы в `core`, `pointers`, `algorithms`, `sequences`, `trees`, `sets` и `dictionaries` одинаковы в обеих работах. Это самостоятельные копии: каждая работа собирается отдельно, без подключения соседнего проекта. `core/IPriorityStorage.hpp`, `heaps` и `queues` остаются только здесь; тематическая индексация — во второй работе.

В `trees`, `heaps`, `sets`, `queues`, `demo` и `benchmark` объявления находятся в `.hpp`, реализации — в соседних `.tpp`. Заголовок сам подключает свой `.tpp` в конце, поэтому в коде достаточно включать `.hpp`; отдельно компилировать `.tpp` не нужно. Библиотечные `pointers`, `sequences`, `dictionaries`, `core`, `algorithms` и небольшие описания типов в `domain` остаются в заголовках.

- AVL: вставка, поиск, удаление, шесть обходов в глубину и обход по уровням, `Map`, `Where`, `Reduce`, слияние, поддеревья и пути.
- Множество на AVL: операции над множествами, включение, равенство, функциональные операции и операторы.
- Очередь на AVL или куче: повторы и равные приоритеты, диапазоны, поиск подпоследовательности, слияние и разделение.
- Отдельная бинарная куча на своём массиве: базовые операции и линейное построение.
- Отсортированная последовательность: вставка с сохранением порядка, поиск и удаление через двоичный поиск.
- Словари: отсортированный массив, AVL и хеш-таблица с цепочками; общий интерфейс `IDictionary<K, V>`.

Деревья, множество и очередь сохраняются как значения через пробелы: `1 2 3 4 5 6`. При чтении значения добавляются обычной вставкой; точная форма исходного дерева не сохраняется. Пустая строка даёт пустую коллекцию. Значения с пробелами, кавычками и пустые строки заключаются в кавычки; это позволяет сохранять строки и записи целиком. Повторы в очереди сохраняются.

`IEnumerable<T>` задаёт только перебор. `ICollectible<T>` расширяет его размером и проверкой пустоты; от него наследуются интерфейсы последовательностей, множеств и словарей, а также дерево, куча и очередь. `IPriorityStorage<T>` расширяет `ICollectible<T>` операциями с приоритетом. `PriorityQueue<T>` владеет хранилищем через `UniquePtr`; компаратор принадлежит хранилищу. По умолчанию используется AVL, явно выбрать можно так:

```cpp
PriorityQueue<int> treeQueue(MakeUnique<TreePriorityStorage<int>>());
PriorityQueue<int> heapQueue(MakeUnique<HeapPriorityStorage<int>>());
```

Копирование и функциональные операции сохраняют хранилище и компаратор. `Clone` создаёт независимую копию, `CreateEmpty` — пустое хранилище с той же политикой приоритета. Перебор обоих хранилищ идёт по убыванию приоритета и возвращает ссылки на исходные элементы. Для кучи он подготавливает отсортированный список указателей за O(N log N) и O(N) памяти; вставка и извлечение остаются O(log N), вершина — O(1). У AVL вершина — O(log N), обход — O(N).

```sh
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j 4
ctest --test-dir build --output-on-failure
./build/structures
```

При запуске открывается меню. Демонстрация — пункт 9. Консоль работает с целыми и вещественными числами, строками, комплексными числами, студентами, преподавателями и указателями на функции. Ручной ввод и генерация с seed доступны в меню. У очереди выбирается AVL или куча. У записей AVL сравнивает ID, очередь — оценку студента или стаж преподавателя. Для функций используются имена `square`, `negate`, `increment`. При первой сборке тестов CMake загружает GoogleTest; сборка без тестов — `-DBUILD_TESTING=OFF`.

Бенчмарк — пункт 8 в меню. Он выводит таблицу в консоль, без файлов. Для обычного прогона укажи максимальный размер `1000000` и лимит `1` секунду; для крупного — например, `10000000` и `2` секунды.

Размеры: 10 000, 100 000, 1 000 000, 10 000 000, 100 000 000. Порядки: Ascending, Descending, Random. `N` — размер входа в серию, `Операций` — фактически выполненное число вызовов; для операций над множествами это один полный вызов. `limit` отмечает достижение лимита. Он проверяется между пакетами операций, отдельный вызов не прерывается. Размеры 10⁷–10⁸ запускаются явно при достаточной памяти. Графики из исходного условия не входят в текущую консольную версию.

`QueueAVL` и `QueueHeap` сравнивают одинаковые операции очереди на двух хранилищах.

Владение — через свой `UniquePtr`. Копирование структур глубокое. Перечислитель возвращает ссылки на исходные элементы; коллекция должна жить дольше него и оставаться неизменной. Изменение дерева инвалидирует его перечислители. Порядок равных приоритетов очереди не фиксирован. `Map` AVL и множества объединяет эквивалентные результаты; очередь сохраняет повторы. `Reduce` вызывает `f(элемент, аккумулятор)`.

У дерева есть константная и изменяемая перегрузки `Find`. Изменяемая нужна словарю для обновления значения без замены узла. Менять поля, участвующие в сравнении дерева, через полученный указатель нельзя; словарь открывает изменяемый доступ только к значению, сохраняя ключ.

Все тесты первой работы находятся в `tests.cpp`, включая проверки совместимости контейнеров через `ICollectible`, словарей, расширенных операций дерева и множества, времени жизни элементов массива и общих алгоритмов.

Собственный массив требует конструируемые по умолчанию и присваиваемые элементы; хранилища очереди — копируемые элементы и компаратор для клонирования. Компаратор задаёт строгий слабый порядок, для точного поиска в очереди и куче требуется `==`. Строковые преобразования нестандартных типов передаются функциями.

```sh
cmake -S . -B build-sanitizers -DCMAKE_BUILD_TYPE=Debug -DENABLE_SANITIZERS=ON
cmake --build build-sanitizers -j 2
ctest --test-dir build-sanitizers --output-on-failure
./build-sanitizers/structures
leaks --atExit -- ./build/structures
```
